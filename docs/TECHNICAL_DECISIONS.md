## Разделение на три независимые БД (решение, 2026-11-24)

- **Решение (пользователь):** архитектура фиксируется — две независимые
  БД данных + отдельная служебная. Первая — синтетическая ФИС ГИА
  (`mai_fis_gia`), источник результатов ЕГЭ, доступная Hermes только через
  MCP (чтение). Вторая — собственная БД MAI-Agent (`mai_agent`):
  абитуриенты, баллы, заявления, рейтинги; доступная Hermes через SQL
  (`sql_query`, открытый доступ демо-версии). Агент самостоятельно переносит
  данные из ФИС в свою БД и работает с ними. Служебная БД Backend
  (`mai_backend`: `agent_sessions`, `telegram_checkpoints`) остаётся
  отдельной и не видна ни одному MCP-инструменту.
- **Интернет:** Hermes использует собственные инструменты (терминал,
  curl, Python) — штатные web_search/web_extract в среде не работают,
  отдельный MCP-инструмент веб-страниц не предусмотрено.
- **Граница ответственности:** Backend остаётся транспортным мостом
  (Web/Telegram ↔ ACP ↔ Hermes, MCP-хост, служебная БД); вся предметная
  бизнес-логика выполняется Hermes.
- **Реализация:** `app/init_databases.py` (идемпотентное создание
  `mai_agent`/`mai_fis_gia`, схема собственной БД, автозагрузка фикстуры
  ФИС; вызывается в entrypoint перед alembic), три движка в `app/db.py`,
  миграция `0014_drop_external_data` (служебная БД — только служебные
  таблицы), `docker-compose.yml` (служебная БД `mai_backend`),
  `backend/hermes-profile/SOUL.md` (раздел «Архитектура данных»).
- **Проверка запуска (2026-11-24).** При переключении БД передаём объект
  `sqlalchemy.engine.URL` в `create_engine`, чтобы сохранить пароль.
  Docker Compose поднял все три сервиса, Alembic применил ревизию
  `0014_drop_external_data`, подключения к трём БД и `/ready` проверены.
